---
title: Desktop
description: Test a native desktop app on macOS through its accessibility tree.
---

`@e2e-dev/desktop` runs tests on native desktop apps. It reads and drives
the app through the OS accessibility tree with
[agent-desktop](https://github.com/vercel-labs/agent-desktop). Tests use the
same `agent`, `screen`, and `expect` APIs as browser tests.

<Note>
  The desktop engine is a prototype, and it runs on macOS only. A config with
  a desktop target still loads on Windows and Linux, so its other targets run
  there, but the desktop target fails to start.
</Note>

## Set up

Install the runner and the engine:

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/desktop
```

```bash pnpm
pnpm add --save-dev e2e @e2e-dev/desktop
```

```bash bun
bun add --dev e2e @e2e-dev/desktop
```
</CodeGroup>

On macOS, the app that starts e2e needs two permissions in **System Settings
> Privacy & Security**. That app is your terminal, your IDE, or your CI agent.

- **Accessibility**, to read and drive the app.
- **Screen Recording**, for screenshots.

The first run downloads agent-desktop and checks its SHA-256 digest. To use
your own install, such as a Homebrew one, set
`desktop({ binary: '/path/to/agent-desktop' })`.

Check your setup:

<CodeGroup>
```bash npm
npx e2e doctor
```

```bash pnpm
pnpm exec e2e doctor
```

```bash bun
bunx e2e doctor
```
</CodeGroup>

It checks agent-desktop, both permissions, and the `appPath` build.

## Point at your app

Set the target's `app.appPath` to a built `.app` bundle. Or set
`app.bundleId` to an installed app's bundle id or name, such as
`com.apple.TextEdit`. With both, the `appPath` build is launched, and its
bundle id must be `bundleId`. `app.launchArguments` go to every launch.

The app gets only these variables of the run's environment: `HOME`, `USER`,
`LOGNAME`, `SHELL`, `PATH`, `TMPDIR`, `LANG`, `LC_*`, and
`__CF_USER_TEXT_ENCODING`. Secrets, model keys, and CI tokens in the
environment never reach it. The engine also sets `E2E_DESKTOP_LAUNCH`, a
token it uses to find the copy it launched.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { desktop } from '@e2e-dev/desktop';

export default {
  targets: [
    {
      name: 'mac',
      engine: desktop(),
      app: { appPath: 'build/MyApp.app' },
    },
  ],
  credentials: {
    ada: { username: 'ada', password: process.env.ADA_PASSWORD ?? '' },
  },
} satisfies E2EConfig;
```

## Write a test

Import `test` from `@e2e-dev/desktop`. `app.open()` launches the app in the
background, so it does not take your keyboard. When the engine launched it
before, it quits that copy first. A copy you opened yourself is left alone,
and the engine never reads or drives it. Every test ends with the app quit,
and no window the app saved at its last quit comes back.

```ts title="tests/sign-in.e2e.ts"
import { test } from '@e2e-dev/desktop';
import { credentials, expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  const ada = credentials.user('ada');
  await app.open();
  await screen.getByRole('textbox', 'Username').fill(ada.username);
  await screen.getByRole('textbox', 'Password').fill(ada.password);
  await screen.getByRole('combobox', 'Plan').selectOption('Team');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByTestId('status')).toContainText('Signed in as ada');
});
```

Roles use the names the web uses: `textbox`, `checkbox`, `combobox`,
`button`. Static text has the role `text`, so find it with `getByText`. A
control's name is the one macOS accessibility gives it: its title, or its
accessibility label. Text inside a button is only in the button's name, so
find the button with `getByRole`, not `getByText`. `getByTestId` finds the
control's `AXIdentifier` (`accessibilityIdentifier` in AppKit, SwiftUI's
`.accessibilityIdentifier`).

The `desktop` fixture lists the app's windows (`desktop.windows()`), picks
the one `screen` reads (`desktop.useWindow(window)`), and quits the app
(`desktop.closeApp()`).

## What differs from the web

| Area | On a desktop target |
| --- | --- |
| Input | The app runs in the background, and actions use the accessibility API, so your pointer, focus, and typing stay where they are. An app that opens no window in the background, such as a document-based one, is brought forward once |
| Physical input | `doubleTap`, `hover`, point taps, and typing into whatever has focus need `desktop({ headed: true })`, which brings the app forward and uses the real pointer and keyboard |
| Keys | `press` on a control sends the key only while that control has focus, in the window the app sends keys to. An app in the background gets keys by its name, so while another copy of it runs, such as a second desktop target on the same app, `press` needs `headed: true` |
| Select | `selectOption` takes an option's label, not an index |
| Windows | `screen` reads one window of the app: the one `desktop.useWindow()` picked, else the focused one, else the first visible one. Sheets are part of their window. The window's own Close, Minimize, and Zoom buttons are left out |
| Menu bar | The app's menu bar cannot be read yet. Use a key shortcut with `press` |
| Web content | Text in a browser window, an Electron app, or a web view is not supported. Test web apps with `@e2e-dev/web` |
| Workers | One per target, because its workers would share one screen. Two desktop targets can still run at the same time: with `headed: true`, set `workers: 1` in the config |
| State | `app.clearState()` is not supported |
| Secrets | A password field shows no value, and screenshots paint it black |

A screenshot that cannot cover a password field is not saved. agent-desktop
keeps the text of other fields in each worker's private state directory. The
engine removes it when the worker ends. The next run removes one a killed
worker left behind, and quits the app that worker left running.

## Options

| Option | Type | Default |
| --- | --- | --- |
| `binary` | `string` | the downloaded release |
| `snapshot` | `'full' \| 'interactive'` | `'full'` |
| `headed` | `boolean` | `false` |
| `settle` | `number \| false` | `150` |

`snapshot: 'interactive'` reads only controls, without static text. `settle`
is how long the engine waits after an agent action before the agent reads
the screen, in milliseconds.
